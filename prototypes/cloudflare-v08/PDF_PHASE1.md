# PDF Phase 1：必要欄位、來源映射與本機管理預覽

本階段只實作本機解析、年份／日期確認、資料模型及管理預覽。未部署，也未串接無員編的中央發布／護理師流程。登入、KV、限速、SYNTHETIC_ONLY 與交換演算法均不更動。

## 解析與資料邊界

- 姓名必填，員編選填。姓名或員編表頭不唯一仍阻擋。
- PDF 先依文字座標建立各頁表頭、日期順序、欄間距與欄界；只在可追溯映射中擷取每日班別。
- 日期範圍外的附加欄，依位置分類成 outsideDateRegion，名稱不作忽略白名單。原表頭、值與來源保留於 pdfNonDailyColumns，不送入 shifts。
- 日期範圍內的未知欄、疑似未辨識日期的外側表頭、缺漏／重複日期、跨頁不一致、班別碰撞及跨越必要欄界仍阻擋。無法證明是附加欄時不猜測。
- 附加欄不提供年份。缺年份先保留原始日期欄與 pendingShifts；管理員明確確認「第一個日期欄」的西元年後才重建精確日期。不採檔名、系統年份或附加欄名稱推定。
- ImportConfirmation.confirmYear(model, year) 回傳新模型；變更年份撤銷先前週期及日期決策，需重新確認。跨年按日期順序推進，無法唯一對應仍阻擋。
- 保留一次決策同步修正各頁相同日期誤植；以日期欄相對順序分組，但保留各頁原始 index/來源。Model.dateCellsPreserved() 用原始表格逐格對照。
- 正式週期固定連續 28 天；週期外日期保留為安全判斷參考，不能選為交換日期。
- 頁尾僅辨識完整「第 n 頁，共 N 頁」格式，核對實際頁號／總頁數、位於人員列下方最後文字列、無姓名／員編；不使用固定頁數或絕對 y 座標。其他未知尾列仍驗證，不任意略過。
- 空白維持未知／未排定；所有人員列保留。既有未知日期候選排除、連續上班及破碎班規則保留。

## 人員識別

- id 是內部紀錄鍵；employeeNumber 是原始員編或 null。
- 有員編：沿用同一次匯入中以員編合併，姓名／班別衝突仍阻擋。
- 無員編：以本次匯入 scope 與來源表格／列建立 local-record: 前綴的獨立 ID。同名、不同列／頁不自動合併；不同匯入使用不同 scope。
- WeakMap 內的原始表格 context 與 row ID 對照，在年份／日期重建時重用；不以姓名找回或重配 ID。
- sourceRows、pendingShifts、附加欄原值只留本機模型。管理預覽姓名優先，未提供員編不顯示內部 ID 作員編；來源可由列的提示檢視。同名紀錄顯示提醒。

## 發布邊界（不可視為已完成 v2）

既有 publication v1 已可保留週期外日期，不需要為此升版。有員編且通過全部驗證的班表繼續使用 v1。

無員編需要分開內部 ID 與員編的公開資料契約，因此標記 requiresPublicationV2。本階段管理頁停用發布，SchedulePublication.create() 拒絕這類模型，v1 load() 拒絕 local-record: 前綴，避免偷偷把暫時內部 ID 當成真實員編。

下一階段建議 v2 契約：
- 沿用 format、publishedAt、cycle、完整 dates 與 shifts；schemaVersion 明確為 2。
- 增加匯入／發布範圍 scope。
- employees 的 id 是範圍內唯一內部鍵，employeeNumber 是非空字串或 null，name 必填。
- 同名紀錄可帶最小來源顯示標記（頁／列），不含原 PDF、原始檔名或附加欄私有內容。
- 保留讀取 v1，明確選擇 v1/v2 adapter，嚴格驗證未知旗標、日期、班別、大小、重複 ID 與角色授權。
- Worker 必須由伺服器重驗，現有 Cookie、Origin、Session、Secret 與限速不變；synthetic-only 的適用條件也須明確測試，不能因 v2 略過。
- 護理師搜尋顯示姓名與選填員編，不顯示內部 ID；無員編不得跨 scope 記住／對應身分，同名需檢視班表與來源確認，不自動選擇。

以上僅設計，尚未實作 v2 的序列化、Worker 接收／回傳與護理師 UI。Phase 1 不代表無員編已可中央發布。

## 測試原則

自動測試僅用虛構表格／PDF／身分。涵蓋任意名稱附加欄、內部未知欄／外側疑似日期、必要欄跨界、同名不同紀錄與 scope、年份／跨年／閏日、原值追蹤／重建 ID 穩定、頁碼／非頁尾尾列、v1 發布拒絕與管理預覽。真實文件僅在 Downloads 唯讀驗證，彙總結果保存在 Repository 外，不建立真實資料 Fixture。
